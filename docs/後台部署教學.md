# 哇娃衣櫃 AI 後台部署教學（Cloudflare Workers，免費）

做完之後，網頁和 App 的 AI 功能都會先連到**你的後台**，再由後台帶著密鑰去問 AI。
使用者看不到 API 地址和密鑰，也不需要自己設定任何東西。

> ⚠️ 密鑰只填在 Cloudflare 的設定頁，**不要**貼進程式碼、不要傳給任何人、不要放上 GitHub。

整個過程大約 15 分鐘，全部用瀏覽器完成，不用安裝任何東西。
（Cloudflare 的畫面偶爾會改名字或換位置，找不到按鈕時用頁面上的搜尋，或截圖給我看。）

---

## 1. 註冊 Cloudflare

1. 到 <https://dash.cloudflare.com/sign-up> 用 email 註冊，收信點驗證。
2. 免費方案就夠用：每天 10 萬次請求。

## 2. 建立 Worker

1. 左邊選單點 **Workers & Pages**（有時在 **Compute** 底下）。
2. 按 **Create**（建立）→ 選 **Start with Hello World!**。
3. 名字可以取 `doll-ai`，按 **Deploy**。
4. 部署完會看到一個網址，長得像 `https://doll-ai.你的帳號.workers.dev`，**記下來**。

## 3. 貼上後台程式

1. 在這個 Worker 的頁面按右上角 **Edit code**。
2. 左邊的 `worker.js`（或 `index.js`）裡面的內容**全部刪掉**。
3. 打開 GitHub 上這個專案的 `server/worker.js`，按 **Raw** 或複製按鈕，把全部內容貼進去。
4. 按右上角 **Deploy**。

## 4. 填設定（最重要）

回到 Worker 的頁面 → **Settings** → **Variables and Secrets** → **Add**。一個一個加：

| 名稱 | 類型 | 要填什麼 |
|---|---|---|
| `API_BASE` | Text | 你的 API 地址，填到 `/v1` 為止，例如 `https://api.xxx.com/v1`（只填網域 `https://api.xxx.com` 的話，後台會自動補上 `/v1`） |
| `API_KEY` | **Secret** | 你的 API 密鑰（**一定要選 Secret**，存了之後連你自己都看不到，這是正常的） |
| `MODEL_TEXT` | Text | 分析用的模型。名稱請從中轉站的模型清單**整段複製**，例如 Gemini 3 Flash 通常叫 `gemini-3-flash-preview`，有的中轉站前面還要加 `google/`；名稱不對會出現「AI 服務設定有誤（模型或格式）」 |
| `REASONING` | Text | 選填：AI 回答前「想多少」。不填 = `low`（省錢，App 的用途夠用）；覺得分析不夠準可以改 `medium`；填 `off` = 不送這個設定。中轉站不支援時後台會自動改回不送 |
| `ALLOWED_ORIGINS` | Text | `https://shiun-wq.github.io,capacitor://localhost,https://localhost` |
| `REDEEM_CODES` | Text | 選填：兌換碼，格式「代碼:內容」，好幾個用半形逗號隔開。內容寫**數字**＝送點數，寫 **member 加天數**＝送會員幾天。例如 `WAWA-7K3MQ9TX:20,WAWA-P4HN82CW:member30`（輸入 WAWA-7K3MQ9TX 送 20 點，輸入 WAWA-P4HN82CW 送會員 30 天）。後面再加「:數字」是**全部人加起來最多能換幾次**，例如 `SSDOLL:member15:100` 換滿 100 次就失效（不寫就不限次數；有人一直重裝 App 也只能吃掉這些次數）。每台手機每個代碼只能用一次；還是會員時再兌換，天數會接在後面加。同一台手機或同一個網路一天最多輸錯 10 次。代碼建議 10 個字以上、英文加數字亂數，避開 0／O、1／I／L。不想給了就把那個代碼刪掉，按 Save 馬上生效 |
| `TEST_DEVICES` | Text | 選填：測試用，填在這裡的裝置直接當會員。裝置代碼在 App 的 設定 → 開發者模式 最上面，按「複製」貼過來；好幾台用逗號隔開 |

- `ALLOWED_ORIGINS` 規定哪些網址可以用你的後台：GitHub Pages 的網頁，加上之後的 App（iPhone 是 `capacitor://localhost`，Android 是 `https://localhost`）。
- 之後如果網站搬到別的網址，要記得把新網址加進來（逗號分隔、不要有空格也沒關係）。

每加完一個都按 **Save / Deploy**。

## 5. 記帳資料庫（一定要做）

AI 次數、點數、會員、免費試用都記在這個資料庫裡。沒做的話 App 還是能用，但次數和點數只記在使用者手機裡，懂一點技術的人可以自己改掉，任何人拿到網址也能一直打，錢是從你的 AI 額度扣的。

1. 左邊選單 **Storage & Databases** → **D1 SQL Database** → **Create**（建立資料庫），名字取 `doll-db`，其他照預設。
2. 回到 Worker → **Settings** → **Bindings** → **Add** → 選 **D1 database**。
   - Variable name 填 `DB`（要一模一樣，大寫）
   - D1 database 選剛剛的 `doll-db`
3. 按 **Deploy**。

資料表不用自己建，第一次有人用的時候後台會自動建好。

綁好之後，每台手機每個月的 AI 次數照 App 裡寫的方案算（免費、試用、會員），每月 1 號（台灣時間）重置。另外還有兩道保險：

| 名稱（選填，Text） | 預設 | 意思 |
|---|---|---|
| `DAILY_LIMIT` | 30 | 每台裝置每天最多用幾次 AI（會員不受這個限制） |
| `GLOBAL_DAILY_LIMIT` | 300 | 所有人加起來每天最多幾次（最後一道保險，人多了記得調高） |

D1 免費版每天可以寫 10 萬次、讀 500 萬次，上架初期完全夠用。

> 以前做過「KV（QUOTA）」那一步的，綁了 `DB` 之後就改用資料庫記，KV 可以留著不用管。

## 6. 檢查

用瀏覽器打開：

```
https://doll-ai.你的帳號.workers.dev/health
```

看到類似這樣就是成功：

```json
{"ok":true,"api":true,"key":true,"text":true,"db":true,"limit":true,"origins":true,"codes":2}
```

- `ok` 是 `false` → 前三個（`API_BASE`、`API_KEY`、`MODEL_TEXT`）有漏填。
- `db` 是 `false` → 第 5 步的資料庫沒綁好（能用，但不會記帳）。
- `codes` 是你設定了幾個兌換碼。

## 7. 把網址給我

把 `https://doll-ai.你的帳號.workers.dev` 這個網址傳給我（**只要網址，不要密鑰**），我幫你寫進網頁裡，之後所有人打開網頁就會自動走你的後台。

在那之前你可以自己先試：

1. 網頁 → 右上角設定 → **連點「設定」這兩個字 7 下** → 打開開發者模式。
2. 「後台網址」填你的 workers.dev 網址，選「走後台」。
3. 按「連不上？跑一次診斷」，會告訴你哪裡沒設好。

## 常見問題

**Q：出現「這個網址沒有被允許使用 AI」**
`ALLOWED_ORIGINS` 沒包含你現在用的網址。診斷頁會顯示要加的網址。

**Q：出現「AI 服務設定有誤（密鑰）」**
`API_KEY` 填錯，或 API 那邊的額度用完了。重新 Add 一次 `API_KEY` 蓋過去。

**Q：出現「AI 服務設定有誤（模型或格式）」**
`MODEL_TEXT` 名稱打錯。
想看詳細錯誤：暫時加一個 `DEBUG` = `1`，查完記得刪掉（不然使用者會看到上游的錯誤內容）。

**Q：開發者模式要怎麼關？**
設定裡「開發者模式」旁邊的「關閉」。一般使用者不會看到任何 API 相關的設定。

**Q：我自己要怎麼用會員測試？**
App → 設定 → 連點「設定」7 下打開開發者模式 → 最上面「這台手機的裝置代碼」按「複製」→ 貼到 Cloudflare 的 `TEST_DEVICES`，按 Save。回到 App 重新打開，右上角就會變成「♛ 會員」。

**Q：要錢嗎？**
Cloudflare Workers 和 D1 的免費額度對上架初期綽綽有餘。會花錢的只有你原本的 AI API 用量。
